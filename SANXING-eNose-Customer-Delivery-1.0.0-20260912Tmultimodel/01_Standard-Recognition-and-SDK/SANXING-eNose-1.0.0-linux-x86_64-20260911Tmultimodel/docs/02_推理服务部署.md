# 推理服务部署

## 目录结构

```text
sanxing-enose-inference-service-1.0.0-linux-x86_64/
├── application/
│   ├── enose-inference-service
│   ├── resources/
│   ├── model_registry/
│   └── _internal/
├── docs/
├── systemd/enose-inference-service.service
├── BUILD_INFO.txt
└── SHA256SUMS
```

`application/resources/` 是默认模型目录。内置的各设备模型位于
`application/model_registry/SX_01/20260911T142306_enose_core_v1/` 和
`application/model_registry/SX_02/20260911T135526_enose_core_v1/`。

## 命令行参数

| 参数 | 类型/默认值 | 说明 |
|---|---|---|
| `--host` | 字符串，`127.0.0.1` | TCP 监听地址 |
| `--port` | 整数，`5006` | TCP 监听端口 |
| `--bundle` | 目录，默认 `application/resources` | 选择一个模型包目录 |
| `--self-test` | 开关 | 加载并校验模型，成功后输出 `ready` 并退出 |
| `--version` | 开关 | 输出服务版本并退出 |

## 前台运行

```bash
cd sanxing-enose-inference-service-1.0.0-linux-x86_64/application
./enose-inference-service --self-test
./enose-inference-service --host 127.0.0.1 --port 5006
```

按 `Ctrl+C` 安全停止服务。

当前版本一个服务进程同时处理一个客户端连接。客户端断开后，服务接受下一次
连接，并为新连接重新初始化推理状态。

## 选择模型

模型目录必须包含：

```text
manifest.json
model.joblib
class_map.json
runtime_config.json
```

每个服务进程只加载一个设备模型。切换到内置的其他设备模型前先自检，例如：

```bash
./enose-inference-service \
  --bundle model_registry/SX_02/20260911T135526_enose_core_v1 \
  --self-test
```

自检成功后使用相同目录启动：

```bash
./enose-inference-service \
  --bundle model_registry/SX_02/20260911T135526_enose_core_v1 \
  --host 127.0.0.1 \
  --port 5006
```

## systemd 部署

在解压后的推理服务目录执行：

```bash
sudo mkdir -p /opt/sanxing-enose-inference-service
sudo cp -a application /opt/sanxing-enose-inference-service/
sudo cp systemd/enose-inference-service.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now enose-inference-service.service
```

查看状态和日志：

```bash
systemctl status enose-inference-service.service
journalctl -u enose-inference-service.service -f
```

停止、启动和重启：

```bash
sudo systemctl stop enose-inference-service.service
sudo systemctl start enose-inference-service.service
sudo systemctl restart enose-inference-service.service
```

更新模型或程序前先停止服务，替换完成后执行 `--self-test`，再重新启动。

## 跨机器访问

默认 `127.0.0.1` 只允许本机客户端连接。跨机器访问需要把 `--host` 改为服务器
内网地址或 `0.0.0.0`，并在防火墙中仅允许可信客户端访问 TCP 5006。

当前协议为明文 TCP JSONL，不提供 TLS 和身份认证。不要把端口直接暴露到公网；
跨不可信网络时应使用 VPN、SSH 隧道或由部署方提供的安全代理。

## 运行状态检查

```bash
ss -ltnp | grep ':5006'
```

建立 TCP 连接后，服务首先发送一条 `type=ready` 消息。协议请求和响应见
`04_协议说明.md`。
