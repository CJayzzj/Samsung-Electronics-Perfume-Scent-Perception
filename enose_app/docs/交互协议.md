# 电子鼻、机器人主程序与推理程序交互协议

## 数据链路

```text
电子鼻 --COM13二进制帧--> 公开主程序 --TCP JSONL 127.0.0.1:5006--> 推理程序
                              ^                                   |
                              |---- status/result/recovery --------|
```

- 设备编号：`回流1`；采样频率：1 Hz；匹配电阻：10 kΩ。
- 两端缓存各1000帧，约16分40秒。
- 主程序收到一帧就保存一帧，并把同一帧发给推理程序，不发送Excel。
- 每个JSON对象独占一行，使用UTF-8和换行符，禁止`NaN`和`Infinity`。

## 串口二进制帧

电子鼻与`JL_sys_v3_6`使用同一种协议：

- 端口默认`COM13`，115200、8N1；
- 请求命令：`01 03 00 00 00 12 C5 C7`；
- 响应共41字节：`01 03 24`＋16路ADC（大端）＋温度＋湿度＋CRC；
- 温度℃=`raw/100-40`，湿度%RH=`raw/100`；
- 电阻kΩ=`10×ADC/(4096-ADC)`。

## 传感器帧 `sensor_frame`

示例见[传感器帧](examples/sensor_frame.jsonl)。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `schema` | 字符串 | 固定`enose.runtime.v1` |
| `protocol_version` | 整数 | 当前为1 |
| `type` | 字符串 | 固定`sensor_frame` |
| `device_id` | 字符串 | 本轮固定`回流1` |
| `sequence` | uint32 | 每帧加1 |
| `timestamp_ms` | uint64 | 该帧毫秒时间戳 |
| `resistance` | 16个浮点数 | 16路纯电阻，单位kΩ，固定通道顺序 |
| `temperature_c` | 浮点数 | 传感器温度℃ |
| `humidity_rh` | 浮点数 | 相对湿度0～100% |

## 监控消息 `status`

每帧都产生，主程序默认每2秒显示；阶段变化立即显示。

| 字段 | 说明 |
| --- | --- |
| `phase` | `warmup/idle/rising/falling/recovering` |
| `current_score` | 当前帧Score，协议保留完整精度 |
| `peak_score` | 当前气味事件到目前为止的最高Score |
| `baseline_ready` | 基线是否完成预热 |
| `missing_frames` | 本次连接累计丢帧数 |
| `event_id` | 已确认事件编号；无事件时为空 |

## 识别消息 `result`

峰值连续下降3帧后立即分类；一次气味事件只发送一次。

| 字段 | 说明 |
| --- | --- |
| `recognition_status` | `ok`或`rejected` |
| `event_id` | 事件唯一编号 |
| `label` / `class_code` | 香水标签与P01～P04，或闭集异味`异味/O01` |
| `decision_stage` | `closed_binary`表示异味在第一级结束；`perfume_gbt`表示已进入香水四分类 |
| `perfume_probability` | 前置SVM给出的香水概率；只用于当前模型判定 |
| `cigarette_probability` | `1-perfume_probability`，用于调试前置二分类 |
| `binary_threshold` | 香水进入四分类所需的概率阈值 |
| `confidence` | 香水为GBT置信度；异味使用自定义阈值时留空，不等于合同准确率 |
| `peak_score` | 本次事件历史最大Score |
| `response_time_s` | 峰值10%到80%的内部计算结果；终端名为“响应时间” |
| `peak_sequence` | 峰顶帧；模型使用该帧完整16路resp |
| `confirm_sequence` | 连续下降第三帧，即峰值确认帧 |
| `inference_time_ms` | 单次模型推理耗时 |
| `model_id` | 当前模型版本 |

## 恢复消息 `recovery`

恢复从连续下降第三帧确认时刻开始计时。主导通道回到事件冻结基线的±10%，
并连续保持3帧后，发送`status=complete`；300秒仍未恢复时只发送一次
`status=timeout`告警，随后继续监测，不开始下一次寻峰。

| 字段 | 说明 |
| --- | --- |
| `event_id` | 对应的识别事件 |
| `status` | `complete`或`timeout` |
| `dominant_sensor` | 峰顶帧绝对resp最大通道，编号1～16 |
| `current_score` | 当前帧Score |
| `recovery_time_s` | 从第三帧下降确认时刻开始计算的恢复时间 |

## 推理程序内部顺序

1. 校验设备号和16路数据；
2. 加载`回流1`温湿度补偿系数；
3. 更新本帧动态基线；
4. 用本帧补偿电阻和更新后的基线计算16路resp/pattern；
5. 计算`mean(top3(abs(resp_i)/x_cap_i))`；
6. 用`max(abs(resp))`持续寻峰；
7. 从峰顶帧的16路resp按每4路材料组计算group_zscore；
8. RBF-SVM判断为训练过的香烟异味时，对外直接返回`异味/O01`；
9. 判断为香水时，使用同一峰顶帧构造resp＋pattern并进入GBT四分类；
10. 从第三帧下降确认时刻起监测恢复。

本轮模型为`0821_perfume_cigarette_cascade`。当前只对香烟进行闭集异味识别，
未启用马氏距离或咖啡等未知气味开集拒识。
